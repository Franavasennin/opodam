## Findings considered and rejected (so nobody re-audits them)

- **HSTS / security headers on functions**: Netlify enforces HTTPS at the CDN; adding HSTS headers in function responses is redundant. Not worth doing.
- **Supabase anonymous auth "tracks" users**: documented, intentional Supabase behavior (anonymous = no email/password, not no-identity). Not a bug.
- **Trial DST/timezone edge case** (`suscripcion.ts`): worst case ±1h once a year; negligible.
- **Retrieval in-memory index cache** (`retrieval.ts`): runs in ephemeral serverless invocations; no unbounded growth in practice.
- **PostgREST filter-string injection in stripe-webhook**: values come from Stripe API payloads (first-party), not user input; `encodeURIComponent` already applied. Low risk; revisit only if these filters ever accept user input.
- **Stripe webhook ownership verification**: the global `constructEvent` signature check is already correct; per-customer ownership is defense-in-depth only.
- **Prompt injection in LLM system prompt**: the embedded context is the app's own first-party curriculum JSON; users cannot supply custom flashcards/teoria. Revisit if user-generated content is ever fed to the tutor.
